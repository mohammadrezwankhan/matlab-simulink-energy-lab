## CI economics

Keep CI spending efficient while preserving required behavior: avoid duplicate push and pull request validation when the pull request covers the same changes; preserve required check names, branch and release coverage, matrices, tests, and publication or deployment guards. Pin actions to full SHAs, request least privileges, keep lockfiles synchronized, set practical timeouts, and retain artifacts only as long as their evidence requires. Cancel only superseded pull request runs; use unique concurrency keys for non-PR runs. Claim savings only from runtime or billing evidence.
